## Architecture decisions and command map

- Dashboard, list, detail and export share one deny-by-default record-scope predicate. Team users see unassigned/team-owned records, owners see their own records, and explicitly granted collaborators see only their records. Out-of-scope IDs return the same not-found response as absent IDs.
- A02 queues expose scoped new, unassigned, overdue, scan-review and quote counts. A03 supports state, team, owner, service, date, area, unassigned and overdue filters with stable `(created_at,id)` keyset pagination; default is 25 and maximum is 100.
- A04 aggregates explicit DTO queries for the enquiry, append-only activities, tasks and assessments. Mutations use operation grants plus server scope. Enquiry, task and assessment writes require revision checks; missing `If-Match` is 428 and stale revisions are 412.
- Assignment is a command, not a general PATCH. It enforces a singular active owner, team membership and explicit active collaborators. Deactivation atomically unassigns nonterminal enquiries and postpones open tasks with `OWNER_DEACTIVATED_REVIEW_REQUIRED`; it never selects a replacement or expands access.
- Completed human-contact evidence alone sets `first_human_response_at`; failed attempts remain append-only evidence and do not stop the response clock. Overdue remains derived. Follow-up tasks require an owner, due time and purpose; postponement/cancellation require a reason.
- The exact SP 13 transition graph is centralised. Disallowed ordinary transitions return stable `STATE_CONFLICT`. Reopen requires `enquiry:manage`; exceptional override requires `enquiry:override` and a reason. CONTACTED, assessment, QUOTE_SENT, WON and WON→CLOSED enforce their respective evidence guards.
- The Phase 08 boundary is an explicit evidence command for issued quote, dispatch, external commercial confirmation and operational handover. It does not generate or approve a quote.
- A05 supports PROPOSED, CONFIRMED, COMPLETED, CANCELLED and NO_SHOW assessments. Confirmed overlaps are serialised with a PostgreSQL transaction-scoped advisory lock per assignee and rechecked in the transaction. Override needs `assessment:override` plus a reason. Private visits require recorded property-access authorisation; completion requires findings.
- Cutting review uses LIST_REVIEW_PENDING, NEEDS_CLARIFICATION and SPECIFICATIONS_CONFIRMED independently of enquiry state. Confirmation pins the attachment/version, structured snapshot and customer-approval evidence. Production sign-off is separately granted/audited and must reference that exact specification revision.
- A12 exposes redacted audit metadata and notification attempt state. Manual retry is limited to review-required/unknown delivery outcomes. No bodies, contact text, tokens, filenames or bytes are included.
- A12 list and retry queries apply the same enquiry/team/record scope as the operational inbox; holding an audit grant does not reveal unrelated targets or notification attempts.
- Reminder events are generated only in configured weekday business hours, exclude configured holidays and terminal enquiries, and use a unique purpose/window semantic key so concurrent workers cannot duplicate the event.
- Export is explicitly granted, scope-filtered, bounded to 100 rows per request and neutralises spreadsheet formula prefixes.
- The staff UI now exposes keyboard-operable commands for activity evidence, tasks, assignment and assessments. Native modal dialogs provide browser focus containment, Escape/cancel behavior, labelled fields, sticky visible actions and responsive viewport bounds. A 412 produces explicit refresh/reapply guidance rather than an overwrite.
- The local OIDC library's post-callback fallback is now an explicit sign-in/recovery route instead of falling through to the not-found page. Browser verification uses the real local Authorization Code with PKCE flow, establishes a revocable staff session, and follows in-app navigation so the intentionally memory-only session handle is retained.

- Workload indexes cover dashboard/state/owner/due-time queries, area/created keysets, activities, tasks, assessments and audit targets.

- Demo Owner receives explicit operational grants; administrator status alone remains insufficient. Demo Coordinator receives scoped operate/assign/assessment/cutting grants. Content Editor receives none of the lead grants.

The first-run script creates only the runtime role and assigns the schema to the configured migration role. The Spring `local` profile imports the same repository `.env`, so Maven-launched API/worker processes and containers use one local datasource contract.
